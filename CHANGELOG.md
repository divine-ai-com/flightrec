# Changelog

All notable changes to `flightrec` are documented in this file. This project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- Safe defaults. Each was an opt-out before; services that only your own services call opt back in:
  - Request headers and gRPC metadata (`traceparent`, `X-Trace-Id`, `X-Request-Id`) no longer choose trace IDs. Set `Options.TrustRequestTraceIDs`.
  - Triggered scopes no longer mark responses with `Flightrec-Flush` (gRPC: a trailer). Set `Options.EnableFlushMarker`.
  - `StartNotifier` panics without `WithSigningKey`. Pass `WithoutSigning()` for a channel that only trusted processes can publish on.

  Migration: add `TrustRequestTraceIDs: true, EnableFlushMarker: true` to the `Options` of internal services that use cross-service flush or forward request IDs, and pass `WithSigningKey(key)` (the same key in every service) or `WithoutSigning()` to `StartNotifier`. Without the opt-ins, a custom `GRPCMetadataExtractor` is not called, and the notifier and callers match requests only by an OpenTelemetry trace ID, never by a forwarded `X-Request-Id`. Without a signing option, `StartNotifier` panics at startup. Public-facing services that set `IgnoreRequestTraceIDs` and `DisableFlushMarker` need no change.

### Added
- `Options.TrustRequestTraceIDs`, `Options.EnableFlushMarker` and the `WithoutSigning` notifier option.

### Deprecated
- `Options.IgnoreRequestTraceIDs` and `Options.DisableFlushMarker`: they are the default now. They still override the new options.

## [v0.6.0] - 2026-11-15

Security hardening from a review of the whole package, and a cleaner repository layout. The layout change moves no exported identifier: import paths, the API and every log line are unchanged.

Modules released: core `v0.6.0`, `otelflightrec/v0.3.1` and `grpcflightrec/v0.3.2` (READMEs for pkg.go.dev only). `notifier/redisnotifier` and `notifier/natsnotifier` are unchanged at `v0.3.0`.

### Changed
- With OpenTelemetry middleware inside `HTTPMiddleware`, a scope keyed by a request header (`traceparent`, `X-Trace-Id`, `X-Request-Id`) takes the server span's trace ID when the span starts, as a generated ID already did, so logs and spans agree in either middleware order. The header ID stays an alias: notifier notices for it still reach the scope (and its child scopes), failures are announced under both IDs, the per-trace cap of retained scopes applies to both, and flushed records and the summary line carry it as `flightrec.request_id`. The adoption is journaled, so recovered records carry the same IDs (#96).
- Repository layout: the root package is organised by concern in 10 files, with machinery in `internal/` (`traceid`, `snapshot`, `notify`, `journal`); community files moved to `.github/`, `RELEASING.md` to `docs/`, and the demo to `examples/demo`.

### Security
- `StartJournal` refuses a lock file (`path.lock`) that is not a private regular file of the current user with one link, instead of locking a file another user planted.
- New guide, [Running flightrec safely](docs/security.md): settings for public-facing services, notifier authentication and channel permissions, sensitive data, where to put the journal, and resource limits.
- With `Retain` or `StartJournal`, `slog.Any` values were copied as JSON only, so `slog.TextHandler` and other handlers that print values with `String` or `MarshalText` showed the raw value: a type that redacts itself in `String` (a password type printing `***`) leaked once either feature was on. Copies now keep both renderings, made as slog's handlers make them (a nil pointer prints `<nil>` instead of panicking). Journals written by this version store both; an earlier version cannot recover records with `slog.Any` values from them, so recover before rolling back.
- Copied `slog.Any` values are capped at 64 KB each, and copying for `Retain` stops once a scope's copies exceed `MaxRetained`, so large values cannot make retention allocate far beyond its limits.
- `WithSigningKey` authenticates notifier messages with HMAC-SHA256 and a timestamp; unsigned, forged and stale messages are rejected. Without it, anyone who can publish on the notifier channel can trigger flushes in every service.

## [v0.5.0] - 2026-11-15

Fixes from the first end-to-end test of the released modules: three services under load, with Redis, NATS, OpenTelemetry export and `kill -9` (see [docs/e2e-report.md](docs/e2e-report.md)). Three changes alter behaviour, listed under Changed.

Modules released: core `v0.5.0`, `otelflightrec/v0.3.0` and `grpcflightrec/v0.3.1` (documentation only). `notifier/redisnotifier` and `notifier/natsnotifier` are unchanged at `v0.3.0`.

Also new: an animated walkthrough and architecture diagrams in the README, and benchmarks of `otelflightrec` against a real OTLP export path (#30).

### Changed
- A local failure is announced to the notifier even when the trace ID was generated by flightrec. Services forward generated IDs to the services they call (in `X-Request-Id`, for example), so those services know them; before, the failure of a request that entered without a trace header never reached them. Services whose IDs are mostly generated (edge services with `IgnoreRequestTraceIDs`) now publish a notice for each local failure; the publish rate limit still applies (#83).
- `HTTPMiddleware` and the gRPC interceptors take the trace ID from the trace already in the request context (an OpenTelemetry span, as reported by `Options.TraceExtractor` or the registered bridge) before request headers. Before, a header such as the `X-Request-Id` a proxy adds overrode the span, so logs carried a different trace ID than the spans and cross-service flush matched the wrong trace. A custom `GRPCMetadataExtractor` is no longer consulted when the context carries a trace, and `Options.TraceExtractor` now ranks above headers instead of below them. Put OpenTelemetry middleware outside flightrec's for the two to agree (#84).
- `traceparent` values are accepted only when valid as the W3C Trace Context specification defines them: lowercase hex, non-zero trace and parent IDs, no version `ff`, and exactly four fields for version `00`. Other values are skipped like an invalid `X-Request-Id` (#84).
- `otelflightrec.SpanProcessor` no longer triggers on an error status or exception event of a client or producer span that records the remote's answer as a client error: `rpc.grpc.status_code` other than the server-fault codes, or `http.response.status_code` below 500. Instrumentation such as otelgrpc marks client spans as errors for answers like `NotFound`, so a 404 flushed every service in the trace, against the documented gRPC rules. Outbound errors without such an answer (connection failures, timeouts, database and third-party calls) still trigger (#85).

### Fixed
- A failed request whose buffered records were all dropped (evicted by `MaxTotal`, or a single record larger than `MaxPerScope`) writes one `buffered records dropped` line with `flightrec.truncated` and `flightrec.dropped_records`. Before, it wrote nothing, and the loss showed only in `Stats` (#86).
- A record too large for a journal entry (about 64 KB encoded) now leaves a marker, so its request is recovered marked `flightrec.truncated`, with `flightrec.dropped_records` on the summary line. Before, the record was left out silently (#87).

## [v0.4.0] - 2026-11-15

Crash recovery: the debug logs of requests in flight when the process is killed (`SIGKILL`, an out-of-memory kill, a grace period that ran out) are recovered on the next start (proposal 0002).

Modules released: core `v0.4.0` and `otelflightrec/v0.2.2`. `grpcflightrec`, `notifier/redisnotifier` and `notifier/natsnotifier` are unchanged at `v0.3.0`.

### Added
- `Recorder.StartJournal(path, opts...)` writes the buffered records of every scope to a memory-mapped ring file that the kernel keeps when the process dies. The file is created with mode 0600 and written with zeros in full; a lock file, `path.lock`, keeps a second process or Recorder off the same path. `WithJournalSize` sets the size (16 MB by default, 1 MB to 1 GB). Memory faults on the file disable the journal instead of crashing. `stop` zeros and removes the file. Linux, macOS and the BSDs; elsewhere `StartJournal` returns `ErrJournalUnsupported`. `ErrJournalRunning` is returned for a second journal on one Recorder. `Stats` gains `JournalRecordsWritten`, `JournalBytesWritten`, `JournalWraps`, `JournalDropped`, `JournalFaults` and `JournalOldestAge` (#70).
- On the next start, `StartJournal` recovers the requests that were in flight when the process was killed, before it returns: their buffered records are written to `Next` in order with their original time, level, attributes and trace context, tagged `flightrec.flush_reason=crash_recovery`, `flightrec.recovered=true`, `flightrec.recovered_host` and `flightrec.recovered_process_start`, followed by one "request interrupted by crash" summary per request. Records are written at least once. A crash during recovery is retried, up to three attempts; damaged entries are skipped; a file at the path that is not a journal is never deleted. `Stats` gains `JournalRecoveredScopes`, `JournalRecoveredRecords`, `JournalCorruptEntries`, `JournalDiscardedFiles`, `JournalAbandonedRecoveries` and `JournalRecoveryErrors` (#71).
- `examples/crash-recovery` kills a server mid-request with `SIGKILL` and shows the recovered logs; CI runs it, along with a test that kills a journaling child process at random moments (#72, #73).

### Fixed
- `otelflightrec.SpanProcessor` counts the memory a buffered span really holds (the SDK span itself, and each attribute, event and link), about ten times more than before, so `MaxBytesPerTrace` and `MaxTotalBytes` now limit memory to what they state. Expect more spans to be dropped under the same limits; a `MaxBytesPerTrace` below about 500 bytes now drops even the root span (#66).
- `otelflightrec.NewLogHandler` writes `uint64` attribute values above the `int64` range as decimal strings instead of wrapping them to negative numbers.

## [v0.3.0] - 2026-11-15

Cross-service flush: a failure in one service keeps the logs of the other services that handled the same request (proposal 0001).

Modules released: core `v0.3.0`, `grpcflightrec/v0.3.0`, and the new `notifier/redisnotifier/v0.3.0` and `notifier/natsnotifier/v0.3.0`. `otelflightrec` is unchanged at `v0.2.1`.

### Changed
- Trace ID headers with whitespace, quotes, control characters, non-ASCII bytes or more than 128 bytes are no longer used; such requests get a generated trace ID instead. IDs such as UUIDs, ULIDs, base64 and `host/sequence` request IDs are unaffected (#49).

### Added
- `HTTPMiddleware` sets the `Flightrec-Flush` response header (`flightrec.FlushHeader`) when a scope is triggered before its headers are written, so callers can keep their own logs for the same request. The value is a built-in reason such as `http_502` or `slow_request`; custom `Flush` reasons are sent as `explicit_flush`. `Options.DisableFlushMarker` turns the header off for services that answer external clients. The header is removed from incoming requests. `Stats` gains `FlushMarkersSent` and `FlushMarkersMissed` (#39).
- `NewTransport` wraps an `http.RoundTripper` so that a `Flightrec-Flush` header on a response triggers the caller's scope with reason `downstream:<reason>`; the flush then travels up the call chain. A value that is not exactly one built-in reason is ignored and counted, and the header is removed from the response. `MarkerValue` and `ValidMarker` expose the sending and checking rules for integrations. `Stats` gains `DownstreamTriggers` and `MarkersRejected` (#40).
- `Options.Retain` keeps the buffer of a healthy scope for a window after it ends, within its own byte limit `Options.MaxRetained` (default 16 MB) and at most 8 scopes per trace ID. `Recorder.FlushTrace(ctx, traceID, reason)` writes the retained scopes for a trace. `slog.Any` values, including those added with `Logger.With`, are copied when a scope is retained, so later changes to the objects do not show; `slog.JSONHandler` writes the copy as the original JSON and `slog.TextHandler` as JSON text. Expired scopes are released by a timer even without traffic. The summary line of a retained scope carries `flightrec.retained_records`. `Stats` gains `RetainedScopes`, `RetainedBytes`, `RetainedOldestAge`, `RetainedFlushed`, `RetainedExpired` and `RetainedEvicted` (#42).
- `Notifier` and `Recorder.StartNotifier(ctx, n)` connect Recorders in different processes: a local failure announces its trace ID once, and other processes flush their retained scopes and trigger their running scopes for that trace with reason `remote:<reason>`. Scopes triggered by a remote notice or a downstream marker do not announce, so notices cannot echo. Publishing is queued, batched and rate limited, delivery is rate limited, malformed notices are dropped, and the subscription is retried with backoff. A local failure also flushes retained scopes for the same trace in the same process. `notifier/memnotifier` provides an in-process `Notifier` for tests and examples. Generated trace IDs are never announced, and messages over 64 KB or with more than 64 notices are rejected. `Stats` gains `RemoteFlushes` and the `Notifier*` counters (#43).
- `Scope.SendFlushMarker` and `ReceiveMarker` let integrations for other protocols send and receive flush markers with the same rules and counters as `HTTPMiddleware` and `NewTransport` (#41).
- `grpcflightrec`: server interceptors set the `flightrec-flush` trailer (`grpcflightrec.FlushTrailer`) when the scope is triggered, including when the handler panics, and new `UnaryClientInterceptor` and `StreamClientInterceptor` (unary, server-, client- and bidi-streaming) read it and trigger the caller's scope with `downstream:<reason>`. Server interceptors honor `IgnoreRequestTraceIDs` and `DisableFlushMarker`. Requires core `v0.3.0` (#41).
- New module `notifier/redisnotifier`: a `Notifier` over Redis pub/sub (`github.com/redis/go-redis/v9`). `WithChannel` separates environments sharing a Redis server, and idle subscriptions are checked with PING (`WithHealthCheckInterval`) so a connection that died without closing is detected and resubscribed (#44).
- New module `notifier/natsnotifier`: a `Notifier` over NATS core subjects (`github.com/nats-io/nats.go`), with `WithSubject` to separate environments. Reconnection and dead-connection detection are left to the NATS client; a connection closed for good makes `Subscribe` return an error (#45).
- `examples/cross-service`: three services showing cross-service flush for a synchronous failure (response markers) and an asynchronous one (retention and a notifier), in one process or with Docker Compose and Redis. README section "Keep logs across services" (#46).

### Fixed
- Memory accounting no longer adds the size of `Logger.With` attributes to every buffered record. Those attributes live once on the child logger, so `MaxPerScope`, `MaxTotal` and `BufferedBytes` over-counted requests that log through a child logger (#53).
- An informational response such as `103 Early Hints` no longer becomes the recorded status of the request; the final status is used for the 5xx trigger and the summary line (#47).

### Security
- Trace IDs taken from `X-Trace-Id`, `X-Request-Id` and the matching gRPC metadata, and from a custom `GRPCMetadataExtractor`, must be 1 to 128 bytes of letters, digits and `_ . : - / + = @`. An invalid value is skipped: the next header is tried, then an active OpenTelemetry span, then a generated ID. When a header repeats, the first valid value wins (#49).
- `Options.IgnoreRequestTraceIDs` stops `HTTPMiddleware` and the gRPC helpers, including any custom `GRPCMetadataExtractor`, from taking trace IDs from incoming requests, for services that face clients outside your system (#49, #56).

## [grpcflightrec/v0.2.1, otelflightrec/v0.2.1] - 2026-11-15

The core module is unchanged at `v0.2.0`.

### Fixed
- `otelflightrec` and `grpcflightrec` now require core `v0.2.0` instead of a zero pseudo-version and `v0.1.0`, so they install from the module proxy. `otelflightrec/v0.2.0`, `grpcflightrec/v0.1.1` and `grpcflightrec/v0.2.0` are retracted (#23).
- `otelflightrec.SpanProcessor` no longer tracks spans that are recorded but not sampled. They pass through to `Next` unchanged instead of holding a trace entry until `MaxTraceAge` (#24).

### Security
- `grpcflightrec` requires `golang.org/x/net` v0.60.0, which fixes GO-2026-6603, GO-2026-6611, GO-2026-6612 and GO-2026-6617 in the HTTP/2 code that gRPC uses. Previously the minimum was v0.58.0 (#31).

## [v0.2.0] - 2026-11-15

### Added
- `otelflightrec` submodule (`github.com/divine-ai-com/flightrec/otelflightrec`) providing `SpanProcessor` (`go.opentelemetry.io/otel/sdk/trace.SpanProcessor`) that buffers finished child spans per trace in bounded memory (`MaxBytesPerTrace`, `MaxTotalBytes`) and exports them only when the trace or its linked `flightrec.Scope` triggers (#18).
- Configurable healthy-trace export policies on `otelflightrec.SpanProcessor`: `HealthyExportRootOnly` (default: exports only the local root span annotated with `flightrec.dropped_spans` and discards child spans) and `HealthyExportNone` (exports nothing for healthy traces), plus `flightrec.flush_reason` and `flightrec.truncated` attributes on triggered traces (#19).
- `otelflightrec.NewLogHandler` (`log/slog.Handler`) bridging `log/slog` and `flightrec.Recorder` to OpenTelemetry Logs (`go.opentelemetry.io/otel/log`) with original timestamps, structured group/attribute mapping, and `slogtest.TestHandler` compliance (#20).
- Zero-allocation log-time `TraceContext` (`TraceID`, `SpanID`, `TraceFlags`) capture in `flightrec.Recorder`, emitting `flightrec.span_id` on output records when an OpenTelemetry span was active at log time and restoring the log-time `SpanContext` into `ctx` when flushing buffered records to `Next.Handle` (#20).
- Bidirectional `ScopeObserver` hooks (`Recorder.AttachObserver`, `ScopeFromContext`, `Scope.AdoptGeneratedTraceID`) so `otelflightrec.SpanProcessor` and `flightrec.Recorder` coordinate triggers and trace IDs regardless of middleware wrapping order (#18, #20).

## [v0.1.1] - 2026-11-15

### Changed
- Raise minimum Go version in `go.mod` from `1.24` to `1.26` and update CI to test Go `1.26` and `1.27` (#13).
- Deprecate `Options.PassLevel` and `Options.BufferLevel` in favor of `Options.PassLeveler` and `Options.BufferLeveler` (`slog.Leveler`) (#7).

### Added
- `Options.PassLeveler` and `Options.BufferLeveler` (`slog.Leveler`) so `BufferLeveler` can be set to `slog.LevelInfo` (`0`) (#7).
- `grpcflightrec` submodule (`github.com/divine-ai-com/flightrec/grpcflightrec`) providing `UnaryServerInterceptor` and `StreamServerInterceptor` with incoming gRPC metadata trace ID extraction, plus `InvokeGRPCStream`, `WithIncomingMetadata`, and `ExtractTraceIDFromMetadata` in the root package (#10).

### Fixed
- Rebuild a single nested group/attribute tree per record so interleaved `WithGroup` and `WithAttrs` calls never emit duplicate JSON keys or drop attributes; pass `testing/slogtest` out-of-scope, in-scope pass-through, and in-scope buffered-and-flushed (#2).
- Enforce `MaxTotal` across long-lived, initially empty, and previously evicted scopes, and link/unlink scopes atomically under `Scope.mu` so closed scopes cannot remain linked in the eviction list (#3).
- Allocate per-scope ring buffers lazily on the first buffered record and account for ring-buffer slot capacity against `MaxPerScope`, `MaxTotal`, and `Stats().BufferedBytes` (#4).
- Pass through and count records logged against a request context after `Scope.End` instead of dropping them silently (#5).
- Preserve `Options.Next` delegation for out-of-scope logs (keeping startup/background `Info` logs working and `.With` loggers zero-alloc) while documenting the in-scope vs. out-of-scope level rule (#6).
- Default `PassLevel` to `slog.LevelWarn` when only `BufferLevel` is set (#7).
- Resolve `slog.LogValuer` attributes at log/buffer time rather than flush time (#8).
- Trigger `grpc_error` flushes only on gRPC server-fault codes (`Unknown`, `DeadlineExceeded`, `Unimplemented`, `Internal`, `Unavailable`, `DataLoss`) or non-gRPC errors (excluding `context.Canceled`), and emit `grpc.code` instead of HTTP `status` on gRPC summary records (#9).
- Conditionally preserve `http.Flusher`, `http.Hijacker`, and `io.ReaderFrom` on the wrapped `http.ResponseWriter` without falsely claiming `http.Hijacker` or `http.Pusher` (#11).
- Treat `http.ErrAbortHandler` as a normal response abort rather than a panic flush (#12).

## [v0.1.0] - 2026-11-15

### Added
- `Recorder` implementing `log/slog.Handler` with `PassLevel` and `BufferLevel` splitting.
- Per-request `Scope` management with five automatic flush triggers (`error_log`, `http_5xx` / `grpc_error`, `panic` with re-panic, `slow_request`, and explicit `flightrec.Flush(ctx, reason)`).
- Bounded memory management: per-scope ring buffer cap (`MaxPerScope`, default 256 KB) and process-wide oldest-scope eviction cap (`MaxTotal`, default 64 MB).
- `Stats()` snapshot exposing active scopes, buffered bytes, and drop/eviction counters.
- `HTTPMiddleware` for `net/http` with W3C `traceparent`, `X-Trace-Id`, and `X-Request-Id` extraction.
- `InvokeGRPCUnary` zero-dependency gRPC server interceptor helper.
- Reproducible benchmark suite (`benchmark_test.go`) and 1,000-request volume/fidelity demo (`cmd/demo`).
